# Information-gap-driven Tool Use Demo

以下材料、公司、岗位、候选人和历史记录均为虚构。工具名表示宿主无关的逻辑能力，不代表固定 API 调用。

## 虚构场景

- 公司：青岚物流（虚构）
- 岗位：AI 产品经理
- `role_key`：qinglan-logistics-ai-pm
- 面试阶段：专业一面，`standard`
- JD 摘要：负责 AI 客服产品迭代；与算法、工程和运营协作；需要用指标验证产品效果，并能解释取舍和风险。
- 候选人材料摘要：曾参与“霁云客服助手”（虚构）项目，材料提到团队将错误率从 10% 降到 3%，但未说明候选人个人负责的部分。

## 一次完整的缺口驱动流程

### 1. 先检查上下文

当前目标是验证候选人是否能说明一次 AI 产品迭代中的个人贡献和效果证据。上下文里有 JD 原文和候选人回答，但没有有效的 JD 分析，也没有把 JD 要求映射到证据方向。

信息缺口：下一题需要先知道本场应验证的核心要求和证据方向。

工具决策：调用 `analyze_jd`。不调用其他工具。

工具结果摘要：JD 明确要求跨团队推进、指标验证和风险说明；本场先验证“个人动作—指标—结果”的证据链，不设置伪精确权重。

### 2. 发现候选人证据不足

候选人回答：“我们把客服助手的错误率从 10% 降到了 3%。”

`evaluate_answer` 前的状态摘要：回答给出了团队结果，但个人贡献、指标定义和具体动作仍不清楚。

信息缺口：候选人本人做了什么，以及“错误率”如何定义，尚未从当前回答或材料中确认。

工具决策：针对正在验证的 JD 要求调用 `retrieve_resume_evidence`。

工具结果摘要：材料只确认候选人参加了评测集整理和运营反馈同步，没有足够信息证明其独立负责指标下降，也没有错误率口径。

下一动作：`deepen`。

下一问：你本人在评测集整理和反馈同步中具体负责了哪一部分，错误率的统计口径又是什么？

工具结果补齐了“材料中已找到什么”和“仍缺什么”，但没有替 Agent 选择动作。

### 3. 只有同岗位历史相关时才读取复盘

用户说：“请接着上一轮青岚物流 AI 产品经理面试继续。”当前 `role_key` 与历史记录一致，且最近复盘重点是“先给出指标定义，再说明个人动作”。

工具决策：调用 `retrieve_past_review`。

结果最多保留三条重点，并记录最近复盘引用和更新时间。当前 JD 与用户刚才的回答仍优先；历史重点只帮助确定本轮要补的证据。

### 4. 根据补齐的信息做内部判断

`evaluate_answer` 只形成简洁状态摘要：

- 当前问题：已部分回答；
- 完成度：不是明显未完成，但证据链不完整；
- 个人贡献：不明确；
- 指标定义：缺失；
- 因果与取舍：暂不先挑战，先补事实；
- 明确矛盾：未发现；
- 当前主题：尚未充分覆盖。

`select_next_action` 选择 `deepen`，并只生成一个主要问题。内部动作名不展示给候选人。

### 5. 结束并在条件满足时保存

用户主动结束，并说明“下周还要继续练习”。宿主同时提供了明确可写位置 `role-memory/qinglan-logistics-ai-pm.md`，并确认保存范围。

工具决策：调用 `save_session_memory`。

只保存 `role_key`、公司与岗位、最近阶段、会话记录引用、最多三条下一轮重点和更新时间；不保存隐藏思维链、完整简历副本或完整问答副本。若宿主报告写入失败，Agent 必须明确说“本场记忆未保存”。

## 两个不调用工具的例子

### 上下文已经足够

当前上下文已经包含有效 JD 分析、候选人本人负责的动作、指标定义和结果，且会话历史确认该主题已覆盖。Agent 直接执行 `evaluate_answer`，选择 `switch` 并生成一个新的主要问题，不重复调用 `analyze_jd` 或 `retrieve_resume_evidence`。

### 历史复盘与当前岗位无关

用户正在练习另一个 `role_key` 的 HR 面，手头历史记录属于青岚物流 AI 产品经理专业一面，重点与当前目标无关。Agent 不调用 `retrieve_past_review`，只使用当前 JD、当前材料和最新回答做决策。
