# Adaptive Interview Agent Skill

这是一个基于 JD、候选人材料和历史问答，动态决定下一步追问的面试训练 Skill。它的核心不是生成固定题库，而是在每轮根据当前信息选择最有价值的追问动作。

## 为什么做这个 Skill

固定题库式陪练很难处理真实回答中的差异：

- 无法根据回答调整；
- 容易重复、跳题或无限深挖；
- 缺少从面试复盘到下一轮训练的连续性。

## 工作原理

```text
JD + 候选人材料
        ↓
面试阶段 + 面试风格
        ↓
当前回答 + 会话历史
        ↓
clarify / deepen / challenge / switch / end
        ↓
每轮生成一个主要问题
        ↓
复盘 + 下一轮训练重点
```

- 输入包括岗位 JD、候选人简历或项目材料、已发生的问答，以及选定的面试阶段和风格。
- Skill 根据当前回答是否完整、证据是否充分、历史是否已经覆盖相关方向，以及是否存在明确矛盾，选择下一步动作。
- 每轮只输出一个主要问题，使候选人能够用一个回答完成当前任务，也便于保持自然的面试节奏。
- 当当前主题已经充分、存在更相关的未覆盖方向时切题；当本场目标已经合理覆盖或候选人主动结束时收束。

## 核心设计

### 三种面试阶段

- **专业一面**：关注 JD、项目经历、AI 知识与实际应用。
- **业务负责人 / 二面**：关注业务场景、方案判断、个人决策、取舍和跨团队推进。
- **HR 面**：关注求职动机、岗位匹配和行为经历。

### 两种面试风格

- `standard`：保持自然的面试节奏，根据回答进行澄清、深挖、挑战、切题或结束。
- `stress`：表达更直接，证据要求更明确，用于检验个人贡献、指标、因果、取舍和边界。

压力模式只是表达和证据要求更直接，不是第四种面试类型，也不允许攻击、羞辱或人格判断。

### 五种逐轮动作

- `clarify`：回答明显未完成或关键含义不清时，邀请候选人补全当前问题。
- `deepen`：回答已经可理解，但仍需要验证个人贡献、方法、过程、指标或结果证据时继续深挖。
- `challenge`：需要检验取舍、替代方案、因果关系、风险或能力边界时，基于已说内容直接追问。
- `switch`：当前主题已经充分，转向一个与面试阶段和 JD 相关、尚未覆盖的方向。
- `end`：本场已经合理覆盖、继续追问价值较低，或候选人主动结束时自然收束。

## Information-gap-driven Tool Use 与 Memory

Agent 不固定调用所有工具，而是先判断完成下一步面试决策还缺什么信息。只有缺失信息必须从外部材料或历史记录中获得时，才调用相应工具；当前上下文已经足够时直接决策。

### 内部分析与决策

- `analyze_jd`：提取 JD 的核心职责、明确能力要求、优先级和风险点。它本身是内部分析步骤；只有 JD 位于外部文件中时，才先使用宿主文件读取能力。
- `evaluate_answer`：判断回答完整性、个人贡献、指标证据、因果、取舍和明确矛盾。
- `select_next_action`：选择 `clarify / deepen / challenge / switch / end`。

### 外部 Tool Use

- `retrieve_resume_evidence`：按当前岗位要求检索简历和项目材料中的真实证据；已有足够证据时不检索。
- `retrieve_past_review`：用户继续同一岗位训练，或确认使用相关历史复盘且历史与当前目标相关时，检索最近复盘和下一轮重点；当前 JD 和用户最新指令优先于历史记忆。
- `save_session_memory`：面试结束、用户同意保存且写入能力可用时，持久化会话引用和最多 3 条下一轮重点。写入失败时明确说明未保存。

工具不保存隐藏推理、人格标签或整份简历副本。

```text
当前面试目标
        ↓
检查已有上下文
        ↓
识别信息缺口
        ↓
按需检索 JD / 简历证据 / 历史复盘
        ↓
evaluate_answer
        ↓
clarify / deepen / challenge / switch / end
        ↓
生成一个主要问题
        ↓
结束后按需保存岗位记忆
```

Memory 分为两层：

- **Working memory**：本场已问问题、已覆盖主题、待验证信息、明确矛盾和已加载证据；
- **Long-term role memory**：同一岗位最近记录引用、最多 3 条下一轮重点和更新时间。

当前 JD 和用户最新指令始终优先于历史记忆。

## 示例

问题：

`你在这个项目里具体负责了什么？`

候选人回答：

`我们搭了一套评测集，错误率从 10% 降到 3%。`

Agent 判断：

团队结果已经提供，但个人贡献仍不明确。

下一问：

`你本人在这项评测工作中具体负责了哪一部分？`

内部 action 只用于逐轮决策，不会展示给候选人。

## 使用方式

克隆或下载本仓库，并将仓库内容放入宿主 Agent 可发现的 Skill 目录。具体目录和加载方式取决于宿主环境。

触发示例：

- 这是 JD 和简历，请帮我做一场专业一面。
- 请用压力模式进行业务负责人二面。
- 针对上一轮回答继续追问。
- 这是面试记录，请复盘并生成下一轮重点。

详细规则和执行流程见 [SKILL.md](SKILL.md)。

## 边界与限制

- 依赖宿主模型能力。
- 不输出评分、排名或雷达图。
- 不用于招聘决策或候选人能力判断。
- 尚无真实用户规模和业务效果数据。
- 每个场景目前只完成一次规则符合性执行。
