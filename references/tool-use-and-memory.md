# 信息缺口驱动的 Tool Use 与 Memory

本参考文件定义四类宿主无关的逻辑能力。工具名表示能力，不规定具体 API 函数、文件格式或存储实现。Agent 每轮先判断面试目标、已有上下文和信息缺口；只有缺口必须通过工具补齐时才调用对应能力。

## 决策原则

1. 明确当前面试目标。
2. 检查已经可用的 JD、候选人材料、当前回答、会话历史和复盘重点。
3. 识别下一题决策所需但尚未具备的信息。
4. 仅选择能补齐该缺口的必要工具。
5. 将工具结果合并进 Working Memory，并复用仍然有效的结果。
6. 先完成内部 `evaluate_answer`，再选择 `clarify`、`deepen`、`challenge`、`switch` 或 `end`。

如果已有信息足以支持下一题决策，则不调用工具。工具不负责选择面试动作，也不应被固定安排为每轮必做步骤。

## 四类逻辑工具

### `analyze_jd`

目的：读取并分析当前 JD，提取核心职责、明确能力要求、优先级和风险点，并生成本场需要验证的证据方向。

调用条件：JD 尚未读取，或当前解析不足以支持本轮目标。已有有效分析时复用，不重复读取。

输出至少包含：

- JD 中明确写出的核心职责；
- JD 中明确写出的能力要求及相对优先级，用定性描述即可；
- 需要验证的证据方向和风险点。

约束：不虚构 JD 中不存在的要求，不输出伪精确的百分比权重。

### `retrieve_resume_evidence`

目的：针对当前正在验证的岗位要求，从简历和项目材料中检索相关真实证据。

调用条件：当前目标需要的候选人动作、指标或结果在上下文中缺失，且材料中可能存在相关信息。当前上下文已有足够证据时不调用。

输出：

- 已找到的候选人动作；
- 已提供的指标和结果；
- 每条证据的来源；
- 尚未找到的关键信息。

约束：不编造经历，不把团队成果自动归为个人贡献，不读取与当前要求无关的全部材料。

### `retrieve_past_review`

目的：用户继续同一岗位训练时，检索最新相关历史复盘和下一轮重点。

仅在以下情况同时满足时调用：

- 用户要求继续上一轮，或同一 `role_key` 存在历史记录；
- 历史重点与当前面试目标相关。

最多输出：

- 3 条下一轮重点；
- 最值得重答的问题；
- 最近记录引用；
- 更新时间。

当前 JD 和用户最新输入优先于历史记忆。不同岗位、无关历史或当前上下文已有足够相关重点时不调用。

### `save_session_memory`

目的：面试与复盘结束后，保存本场记录和同一岗位的下一轮重点。

仅在以下条件同时满足时调用：

- 用户希望后续继续；
- 宿主提供明确可写位置；
- 保存内容和位置明确。

只保存：

- `role_key`；
- 公司与岗位；
- 最近一次面试阶段；
- 会话记录引用；
- 最多 3 条下一轮重点；
- 更新时间。

不保存：

- chain of thought；
- 人格或心理标签；
- 未经用户提供的事实；
- 整份简历副本；
- 完整问答的重复副本。

写入失败时必须明确说明“未保存”，不能把准备写入或失败的写入声称为已保存。

## Working Memory

本场维护以下工作状态，并在工具结果仍有效时复用：

- 当前面试目标；
- JD 核心要求及优先级；
- 已检索的候选人证据；
- 已问问题；
- 已覆盖主题；
- 待验证信息；
- 明确矛盾；
- 已加载的历史重点；
- 当前动作。

Working Memory 是当前会话的简洁状态，不是完整问答副本，也不包含隐藏思维链。长期保存必须经过 `save_session_memory` 的调用条件检查。

## 与逐轮动作的关系

工具只补充事实与上下文。完成必要的工具选择和 Working Memory 更新后，Agent 仍须按 [动态逐轮追问](dynamic-follow-up.md) 执行 `evaluate_answer` 和 `select_next_action`，每轮只生成一个主要问题。
